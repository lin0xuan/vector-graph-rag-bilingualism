## 逐题复核与结论

工程修复已验收，准确率尚未达标。最终来源召回增加 25 个百分点，但完整答对只增加 1 题；相对修复前救回 3 题、退化 2 题，差值的配对区间跨过零。本轮不足以证明总体准确率已有稳定提升，且仍明显低于本批轻量版。

- **有效救回：`2docs:359`。** 原先列表编号误报、引用 ID 抄错和答案不完整；最终版本无这些规则告警，完整答对。`2docs:686` 也从 partial 变为 correct。
- **选证与补查闭环：`2docs:583`。** 修复前候选齐全但最终没有证据、答案判错；修复后来源齐全。核验两次触发定向补查，分别加入 7、13 个新候选，最终完整答对。最后核验输出截断时保留了答案。
- **生成稳定性：`2docs:104`、`3docs:480`。** 回答服务返回 `finish_reason=length`，无法解析为完整答案；前者的标准来源已全部到位。前者退化了完整答对指标，后者原来也是未完整答对。不能把这两题归因于没有召回证据。原始响应保存在 `model-responses.jsonl`。
- **核验仍会否决正确的跨文档关联：`3docs:779`。** 最终三份标准来源已齐全，原文明确将山东黄金、具体项目和设备型号关联起来。初稿列出了相应技术点，核验却把这种对应判断为无依据；补查后回答删除了这些技术点。战略目标也读错了，虽然正确目标就在最终原文内。这道题不是单靠增加召回能解决的。
- **回答和核验范围仍不可靠：`3docs:312` 漏掉了参考答案中的另外两个要点；`2docs:473` 混入了其他事件背景。核验请求在修复回合还携带历史批评，部分响应持续重复旧问题；存在被旧批评影响的风险，需要单独验证核验是否只依据当前答案与证据作判断。
- **判分争议保留：`2docs:576` 的评分字段与理由不一致；`2docs:12` 涉及“法规内容相同”和“报道详略不同”的解释差异；`2docs:473` 的部分判分理由也读漏了答案已有的分组。没有按有利方向重评或修改这些标签。

因此，当前中文首版仍不宜替代轻量版。下一步应优先处理回答接口的结构化输出稳定性、核验对当前答案的独立判断与跨文档对应，再验证中文 Jev 的实际效果；本轮没有继续追加付费试验。

正式修复组记录到的查询 token 比修复前减少约 42.2%，但仍为轻量版约 9.94 倍。它没有在本批样本上换来与开销相称的完整答对率。以上均为返回的 token 计量，不是精确账单。
