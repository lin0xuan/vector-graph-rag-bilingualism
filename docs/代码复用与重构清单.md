## 必须新增的模块

1. `routing.py`：文档/问题语言和知识库能力路由，明确联合模式的状态。
2. `models.py`：可追溯的来源、片段、证据 span、问点、索引快照和请求状态。
3. `planning/slots.py`：结构化问点及依赖；保留原问题，不凭空生成事实。
4. `retrieval/lexical.py`、`retrieval/fusion.py`：中文词法检索与多通道合并，保留来源和 slot 归属。
5. `selection/coverage.py`：问点级证据判断、引文定位、预算内覆盖选择与冲突记录。
6. `retrieval/repair.py`：只补缺口的有限轮检索和同文章父/邻块读取。
7. `generation/verify.py`：漏答、数字、主语、时间和引用核验，独立于评测评分器。
8. `storage/snapshots.py`：完整性校验、构建任务恢复、版本发布和跨索引一致性。
9. `observability/trace.py`：逐阶段输入/候选/选择/错误/费用记录；支持后续离线回放。
10. `pipelines/bilingual.py`：第二阶段再实现的跨语言联合检索与回答，不侵入英文默认行为。

## 最小接口约定

- `Pipeline.query(request) -> AnswerResult`：包含最终答案、证据、明确的 complete/partial/failed 状态、实际执行 profile、snapshot 和 trace ID。
- `Pipeline.retrieve(request) -> RetrievalResult`：保留有序证据和诊断；英文通过上游 retrieve 适配，中文可与 query 共用检索编排。
- `IndexManifest`：索引配置与数据完整性指纹。`RunManifest` 另记录查询、回答与评分配置，避免改提示词就必须重建索引。
- `Evidence`：稳定 ID、原文、来源别名、原文位置、语言、所属快照。检索分数和模型推断支持关系放独立字段，不冒充原文事实。
- `Trace`：各通道候选、关系/原文重排、slot 覆盖、补查轮次、实体抽取状态、回退原因、核验与修复、模型用量；敏感凭据禁止入日志。

断点续跑分为三类：索引构建恢复、评测任务恢复、失败题定向补跑。缺证补查是同一次查询的策略，不应与这三类任务恢复混在一起。回答修复也使用独立 attempt ID，保存旧答案便于回归。
