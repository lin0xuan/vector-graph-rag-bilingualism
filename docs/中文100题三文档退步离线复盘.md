# 中文CRUD 100题离线复盘：三文档52%的成因

## 结论与口径

本次只读取已有100题逐题日志、冻结索引和轻量版历史同题结果，没有新增模型调用，没有重评或改动原始分数。三文档当前为26/50（52%），轻量版同题为37/50（74%）：保住24题、救回2题、退步13题，净减少11题。这里的“退步”包含 correct→partial，并非13题都被判wrong。

**主要损失发生在候选召回之后，且评分问题与真实系统错误并存。**

- 三文档50题中，48题候选找齐全部标准来源，来源召回98.67%。最终25题找齐来源，最终来源召回80%。
- 13道退步题全部召回标准来源；11题最终仍保留全部来源。没有一道退步题能直接归因为标准来源没有进候选池。
- 24道未完整答对题按最终来源链路可分为：候选缺来源2题、候选齐但Qwen选证漏来源6题、选中后上下文装配挤掉来源2题、最终来源齐全14题。这是阶段分组，不是互斥的最终因果解释。
- 52%不能直接当作可信的纯检索准确率，也不能直接作为Jev效果：本轮没有同100题的新版无Jev对照；与轻量版还存在提示词、评分预算、流程和调用时间差异。

来源齐全不等于关键事实齐全；缺一个标准来源也不一定缺事实。例如219漏掉的段落与保留段落重复，真正致命的是回答退化成残句。

### 最应区分的三件事

1. **技术失败不等于推理能力差。** 212、500在答案产生前失败；219在stop响应下得到残句。仅提高召回或增加Jev请求不会直接解决它们。短可见输出却报length，也不能仅凭日志认定“答案太长”；缺乏供应商内部输出与计费细节，不能进一步断言原因。
2. **核验有时正确、有时加剧错误。** 379正确抓到政协/金融机构错配，但改写失败回退；527补证后仍沿用旧指控；495、784反复追问缺失或题目本身无依据的关系。不能一概关闭核验，也不能把所有缺证回答当退化。
3. **裁判在偷偷增加评分条件。** 48、649、142等将“参考答案未提及的、有证据支持的细节”当成扣分理由；794是分类争议；495、784是参考本身的事实关系问题。379、50、791也有评分边界争议，但仍有真实回答或语料问题。

本报告不把这些题自动改判正确，也不计算“修正后准确率”。

## 切片、索引与代码核对

对24道三文档失分题的72个按题计标准片段，与原轻量版documents.jsonl逐条核对：70个去除换行后一致；另外2个差异只是全角空格转换及换行。去除空白后72/72一致。本批标准片段未发现事实字符被切片删掉。

这不等于源文本质量好。多处资料原本就拼接其他新闻，包含不同年份、主体和正文边界，且标题统一为“中文新闻”。495、784等还涉及参考答案关系错误。当前证据不足以把这些问题归给新切分器。

代码与日志一致的行为：

- `ChinesePipeline._select`：Jev对候选排序，之后Qwen选句；本批没有观察到Jev直接漏掉已入候选的标准来源。不能排除排序影响选句/预算的间接作用。
- `_pack`：按问点装配完整段落，预算不足可跳过已选段。缺某个来源与缺某个必要事实是两种指标。
- `_answer_payload`：回答能看到选句及完整passages；因此“句子没入evidence”不必然意味着模型没看到。
- `query`：answer和verify处于同一个try；verify异常也被记为`generation failed`。一旦已有答案则保留最近一次答案，并非选择“历史上最好”的答案。
- 修复payload继续带`issues`和可能的`previous_answer`；495、527、784表现出重复旧指控。日志支持怀疑核验锚定，但没有消融，不能证明唯一原因。
- `PROMPTS.plan`要求保留数值条件，不要求凭空新增条件；379生成额外数值问点是模型偏离。`answer`和`verify`对“所有相关项/互补事实”的追求，在宽候选上下文下容易导致答案与核验范围不断扩大。

## 从这批记录能得出的优先级

1. **先建立可核查的评分审计口径**：把覆盖、事实支持、时间/主体归属、参考疑点分别记录。尤其不能用“参考没写”判无依据；也不能据此宽免真实漏答。保留原分数，不事后挑有利答案重评。
2. **回答输出可靠性与核验修复终止优先于扩大召回**：空答案、残句、JSON/length异常、改写失败保留旧错答需要单独统计；新增证据后应重新检查当前答案，已有缺证说明不应无限重复追问。
3. **限制问点和选证的范围扩张**：保住能补事实的高位段，按事件、时间、主体组织证据；不要因模型计划多造一个问点就扩大任务。三文档退步不能靠更多候选或更多Jev调用自动解决。
4. **保留真正需要的核验**：例如379的主体错配、784的集合/子集区别。目标应是纠正可证明的错误，不是逼答案贴合有问题的参考。

以上均为离线诊断和后续方向，本次没有修改运行链路，也没有运行新的付费评测。
